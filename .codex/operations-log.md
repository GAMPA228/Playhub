# B站视频与直播

- 2026-11-12：范围收敛为普通投稿、分 P、官方分享短链和直播间；新增独立“视频解析”页，不改原 TVBox、电视直播和历史存储。参考 YunX-Desktop `3700c1c607eea9517f022318d85cb543f05a85dc` 的识别/平台/媒体分层思路，没有移植其 AGPL 源码或桌面依赖。
- 采用公开网页 API、AVC/AAC DASH 与 HLS，媒体通过绑定会话的签名代理流式输出；Cookie 仅发固定 API。无需 FFmpeg、Chromium 或新数据库；DASH 引擎按需加载。新增解析/媒体容量与 Spider 池独立，不能把这个隔离误解为所有媒体网络都不会争用带宽。
- codebase-memory 重新索引返回 indexed，但仍为旧的 2124 节点/6157 边，Bilibili 符号检索为空；当前图谱不能证明新增调用链。降级使用真实源码、Git diff、全量测试、生产 JAR 与独立浏览器实播验证。
- Chrome MCP 与已有专用 profile 冲突，改用 `.cache/bilibili-smoke` 下隔离的 Puppeteer/Chrome profile；不关闭用户 Chrome、不加入项目运行依赖。测试驱动改为明确 Ctrl+A 清空并核对输入，避免浏览器三击 URL 后追加文本造成假失败。
- 真实窄屏测试发现同一路由缩窄窗口后选中标签被裁切，补充 resize 时自动滚入导航可见区。拖动/换流时浏览器主动断连会引发 Spring 再向媒体响应写 JSON，针对 AsyncRequestNotUsableException 直接结束并释放流容量，避免正常取消导致日志刷屏。
- 真实轮播间“重新检查”暴露前端将 quality=0 传给要求正数的接口而返回 400；刷新请求改为仅携带有效清晰度，补充前端回归测试，并重新验证未开播/轮播重新检查入口。
- 早期媒体专测与根 clean 并行导致构建目录竞争，后续 Maven 均独占串行 clean package；测试结论以最终完整构建为准。发布保持现有服务/JAR/数据目录名称，只增加可选 BILIBILI_COOKIE，无数据迁移；用户已授权本次提交并推送 main。
